# Zapasli Android

Android-клиент сервиса совместного учёта домашних продуктов.

## Текущий статус

Завершён первый полноценный offline-сценарий приложения. Пользователь может просматривать кладовую, фильтровать продукты по сроку годности, добавлять, редактировать и удалять позиции. Данные сохраняются локально в Room и остаются после перезапуска приложения. Для продукта поддерживаются количество, место хранения, штрихкод, срок годности и КБЖУ.

Для каждого push и pull request настроена автоматическая проверка сборки, unit-тестов, instrumented-test APK и Android Lint. Пользовательский offline-путь дополнительно проверяется на Android-эмуляторе.

## Технологии

- Kotlin, Jetpack Compose, Material 3
- Hilt, Room, DataStore, KSP
- Android Gradle Plugin 9.3.2, Gradle 9.5.0
- compileSdk / targetSdk 37, minSdk 26
- Application ID: `ru.zapasli.app`

## Локальный запуск

1. Откройте каталог в Android Studio.
2. Дождитесь Gradle Sync.
3. Запустите конфигурацию `app` на эмуляторе или устройстве с Android 8.0+.

Проверка из терминала Windows:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Проверка Room и полного пользовательского сценария на запущенном эмуляторе:

```powershell
.\gradlew.bat connectedDebugAndroidTest
```

## Архитектура

- `domain/pantry` — модели и контракт кладовой.
- `core/database` — локальная Room-база и DAO.
- `data/pantry` — offline-реализация репозитория.
- `core/preferences` — только несекретные настройки интерфейса в DataStore.
- `ui/pantry` — экран кладовой, форма продукта, состояние UI и ViewModel.

Правила работы с ключами, токенами и уязвимостями описаны в `SECURITY.md`.

## Offline-релиз

Первый законченный offline-сценарий отмечен тегом `v0.1.0-offline`. Тег создаётся только после успешных локальных проверок, прохождения CI и аудита состава коммита на секреты и локальные файлы.

## Ближайшие этапы

1. Сканирование штрихкодов и получение данных о продукте.
2. Авторизация, семейная синхронизация и собственный backend API.
3. Сканирование чеков и массовое пополнение кладовой.
4. Персональные цели питания и дневная калорийность членов семьи.
5. Рекомендации блюд с учётом запасов, КБЖУ и целей.

Продуктовая и техническая документация находится в соседнем каталоге `ZapasliDocum`. Репозиторий задания Netology используется только как источник требований и не изменяется.
